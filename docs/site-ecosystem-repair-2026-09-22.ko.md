# 개인 홈페이지와 DeepWrite의 발전 방향·수선작업표

검토일: 2026-09-22. 범위는 개인 공개 홈페이지와 서비스 간 연결이다. 진행 중인 로그인 강좌의 기능, 데이터, 권한, 제출·피드백은 변경하지 않는다. 첫 단위는 개인 홈페이지와 링크 연결에 한정했고, 후속 단위에서는 공개 특강 전용 헤더만 수정하여 기존 운영 버전 위에 게시했다. 강좌 공통 레이아웃, 인증·서버 코드, 환경 설정과 저장소 바인딩은 보존했다.

## 1. 판단

`www.jeyounson.com`은 모든 기능을 집어넣은 포털보다 **손제연이라는 연구자·교육자의 공개 정체성과 저작물을 설명하는 중심**으로 발전시키는 편이 좋다. 연구자의 이력서와 서비스들의 주소록 중 하나를 택할 필요는 없다. 기존 연구·논문을 보존하면서, 방문 목적에 맞는 입구를 앞에 두면 된다.

권장 정체성은 “법철학 연구와 논증적 글쓰기 교육”이다. 연구의 국제적 독자를 위한 영어를 유지하고, 교육·특강 진입에는 한국어를 병기한다. 현재 공개된 학술 내용으로만 소개를 구성하며, 비공개 원고나 운영 정보를 새 홍보 문구로 사용하지 않는다.

모든 도메인의 디자인·로그인을 통합할 필요는 없다. 공통으로 맞출 것은 저자 표기, 교육 브랜드명, 목적지의 명칭과 접근 조건이다. 논문 읽기, 특강 참여, 로그인 과제 작성은 서로 다른 환경으로 남는 것이 바람직하다.

방문 흐름은 `www → 연구/논문`, `www → 교육 → 공개 특강`, `www → 교육 → 수강생 로그인`으로 단순화한다. 특강 자료를 급히 찾는 방문자를 위해 홈에서 공개 특강으로 가는 직접 링크도 둔다. 공개와 비공개가 같은 DeepWrite 도메인에 있어도 괜찮다. 다만 공개 진입에 로그인을 강요하지 않고, 접근 통제는 메뉴 숨김이 아니라 기존 인증 시스템이 담당해야 한다.

공개 교육 콘텐츠의 이름은 DeepWrite로 일관되게 유지한다. `write`는 새로운 경쟁 브랜드가 아니라 기존 자료의 보관 주소로 설명한다. 전체 자료를 지금 한 저장소로 합치거나 모든 과거 링크를 특강 목록으로 일괄 리디렉션하지 않는다. 후속 통합 시에는 원문별 공개 적합성 확인 → 동일 자료 대응표 → 새 정본 → 해당 경로별 이동의 순서를 따른다.

## 3. 근거와 검토의 한계

- 실서버 `https://www.jeyounson.com`은 최초 확인에서 인증서 이름 불일치로 열리지 않았다. 경고를 우회하지 않았으며, 실제 홈페이지 디자인은 최신 원격 소스 `04fde20`을 새로 Jekyll 빌드한 로컬 화면으로 검토했다. 이것은 실서버 시각 검증과 구별한다.
- 수정 전 1280px 화면은 프로필 아래 장문의 Bio로 바로 이어졌다. 390px 화면에서는 주요 메뉴가 사라져 연구·논문·교육으로 이동하기 어려웠다. 교육 메뉴와 공개 특강 입구가 없었다.
- 출판물의 주제 필터는 클릭 가능한 `span`, 초록은 `href` 없는 링크였다. 키보드 작동과 상태 전달을 보완할 필요가 있었다. 전체 출판물 13건과 기존 연구·에세이·인용 경로는 보존 기준이다.
- GitHub Pages 설정의 사용자 도메인은 `www`였으나 Jekyll `url`과 robots/sitemap의 기준 주소는 이전 `github.io`였다. 원격에만 있던 CNAME 추가 커밋은 수정 전에 fast-forward로 수용했다.
- 실서버 DeepWrite의 공개 특강 목록을 확인했다. 소비자정책론 WAC 특강과 학생용 자료 링크가 로그인 없이 표시되었다. 수업 내부에 진입하거나 운영 정보를 수정하지 않았다.
- `www`의 DNS는 GitHub Pages를 가리키고 CAA 오류가 없으나, 최초 TLS 검사에서 GitHub 기본 인증서만 제공됐다. 인증서 발급 복구와 실제 HTTPS 재검증은 디자인 구현과 별도의 완료 조건이다.

## 5. 구현 방식과 유지관리

개인 사이트는 Jekyll/GitHub Pages를 유지한다. 이번 요구는 CMS나 전체 React 재작성 없이 HTML/CSS, 기존 데이터 파일과 소량의 JavaScript로 충족할 수 있다. 새 탐색 메뉴는 CSS sticky, 초록은 HTML `details/summary`를 사용해 자바스크립트가 없어도 읽기와 이동이 가능하다. 검색은 브라우저 안에서만 수행하며 별도 서버·입력 수집을 추가하지 않는다.

강의 플랫폼은 현재의 Sites 기반 서비스를 독립적으로 유지한다. 여기서의 “통합”은 먼저 정보구조·브랜드·링크·자료 정본의 통합이지, 저장소·로그인·배포의 통합이 아니다. 사이트 전체 검색이나 본격적인 문서 탐색이 필요해지면 오픈소스 정적 검색 등을 비교하되, 현재 13건의 논문 검색에 무거운 새 시스템을 도입하지 않는다.

공통 교육 목적지는 `_data/destinations.yml`에서 관리한다. 특강 일정이나 파일 목록은 이곳에 중복 저장하지 않는다. 비공개 자료, 학생 식별정보, 답안키, 운영 콘솔 링크를 추가하지 않는다. 연구 본문·이력·논문 메타데이터의 사실 변경은 별도 원자료 검증을 거친다.

## 6. 게시 전후 검증

1. Jekyll 빌드와 생성 HTML 검증, 전체 출판물·내부 링크·JSON-LD·대표 주소 확인.
2. 데스크톱/390px/320px에서 홈, 교육, 논문 탐색, 초록, 메뉴 및 스크롤 점검.
3. 로컬 검증 후 승인된 저장소만 커밋·푸시하고, 해당 원격 커밋으로 GitHub Pages 빌드가 성공했는지 확인.
4. 실서버에서 HTTPS, 홈·교육·연구·논문·404 경로, 공개 특강으로의 실제 이동을 다시 확인.
5. 인증서 발급이나 아카이브 점검이 남으면 디자인 완료와 구분해 미완료로 기록한다.

GitHub 도메인 수선 기준: [사용자 도메인 문제 해결](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/troubleshooting-custom-domains-and-github-pages). 사용자 도메인과 올바른 DNS를 보존하고, 인증서 발급이 정체되면 지원되는 재등록 절차를 사용한다. 브라우저 보안 경고 우회나 검증되지 않은 HTTPS 강제 설정은 하지 않는다.

## 7. 후속 단위 결과

`write.jeyounson.com`은 기존 DNS와 주소를 유지한 채 Pages 사용자 도메인을 재등록하여 인증서 발급을 복구했고, 승인된 인증서를 확인한 뒤 HTTPS 강제를 활성화했다. 루트와 주요 기존 경로 9개는 인증서 검증을 포함해 200으로 응답한다. HTTP 이동 시 경로·쿼리가 보존되며, 기존 `/asd/`의 404는 내용이 없는 경로이므로 그대로 남겼다. 자료 파일과 공개 범위는 바꾸지 않았다.

DeepWrite는 최신 운영 v300의 격리된 복사본에서 공개 특강 헤더에 `손제연 홈페이지` 링크를 추가했다. 기존 수업 진입 `/`와 특강 본문·PDF는 보존했다. 목록과 상세 화면에서 새 링크를 확인했고 320px에서 가로 넘침 없이 44px 터치 영역이 확보됐다. 전체 검사 793건에서 779건 통과·13건 건너뜀·기존 문서의 개인 경로 표기 1건 실패가 있었으며, 해당 표기만 정리한 뒤 릴리스·공개 안전성·특강 검사 23건이 모두 통과했다. 린트는 오류 0건·기존 경고 2건, 프로덕션 빌드는 성공했다. 기존 의존성의 설치 경고는 별도 유지보수 대상으로 남기고 잠금 파일이나 강좌 기능을 변경하지 않았다.

Sites의 v301 게시 성공을 확인했고 환경 설정 리비전은 기존 37로 유지됐다. 이 단위는 새 강좌를 개설하거나 기존 과제·제출·피드백의 작동을 검증·변경한 작업이 아니다.

## 8. 자료 정리 단위 결과

공개 아카이브의 76개 문서·첨부파일을 파일별 해시·보존 URL·자료군·신규 재배포 검토 상태로 기록했다. 비어 있지 않은 본문 및 파일의 완전 중복은 발견하지 못했다. 같은 주제의 공개 강의와 로그인 읽기책을 같은 판본으로 취급하지 않으며, 기존 강의·첨부파일은 수정·삭제하지 않는다. 작업 사본 6개와 참고문헌·번역·첨부파일은 새 공개 정본으로 자동 이전하지 않는다.

아카이브의 홈에 최신 공개 특강·주제별 자료·로그인 학습공간을 구분하고, `/archive-guide/`에 주제별 찾아가기를 추가했다. 개인 홈페이지의 교육 안내는 이 안내로 연결한다. 기존에 404였던 돌봄윤리 특강 분류 입구는 원래 파일을 보존하면서 별도 안내 페이지로 복구했다. 신규 자료 공개를 승인한 것과 기존 자료의 인벤토리를 완성한 것은 구분한다.

관리 정본은 공개 아카이브 저장소의 `docs/archive-consolidation-2026-09-22.ko.md` 및 `docs/archive-inventory.json`이다. 이 관리 파일들은 웹사이트 빌드에서는 제외하고 저장소에서 변경 이력을 관리한다. 빌드·자료 목록 일치·주소 충돌·정본 URL·안내 링크·관리 파일 비게시 검사를 CI와 게시 과정에 추가했다. DeepWrite 로그인 서비스의 코드·의존성·데이터·배포는 이 단위에서 변경하지 않았다.
